# Agent 工作机

## 创建前

先在菜单03完成宿主显卡准备，再到08创建系统。无GPU也可以直接建立软件桌面；08不会为了安装工作机而更换宿主内核、安装宿主显卡驱动、清零已有VF或修改网桥。

向导读取当前节点的活动网桥和支持 `images` 的可用存储，并取得空闲VMID。配置不得低于4 vCPU、固定8192 MiB和32 GiB系统盘，默认使用此配置。SSH只接受公钥，不接受或复制客户端私钥。IP、MAC、查看端口可在向导中明确指定，供重建后连接核验。

开头列出的存储和网桥是候选项，随后按VMID、名称、存储ID、网桥的顺序询问。存储和网桥各选一个；VM仅创建一张网卡并连接所选网桥。新目录需先在PVE注册为支持磁盘映像的存储，再在向导中填写它的存储ID。

网络默认使用DHCP。保留MAC或填写“期望IPv4地址”不会把该地址分配给VM，DHCP仍可能给出新地址。SSH／FRPC依赖固定目标时，选择`static`并填写未被占用的IPv4/CIDR、同子网网关和单个IPv4 DNS；静态模式的期望地址须与该IPv4一致。也可以使用路由器上已经配置好的DHCP保留，工具不会修改PVE网桥或路由器配置。

命令行对应参数为 `--address 192.168.50.30/24 --gateway 192.168.50.1 --nameserver 192.168.50.1`，地址应替换为实际网段；只传`--expected-ip`仅做连接结果核验。先查看计划，再创建或显式重建。网络配置写入新VM的Cloud-init，不修改宿主网络。

创建／重建向导会询问**客机 Debian APT 镜像源**，回车默认`tuna`（清华），也可选`ustc`（中科大）或`official`（Debian官方）。命令行使用`--apt-mirror tuna`等固定预设；不传参数以及旧部署记录缺少此字段时沿用官方源。选择写入部署记录，并在计划和状态摘要显示源名称、软件包URL及安全更新URL。只影响新客机的Debian软件包、桌面和驱动依赖，不修改PVE宿主源、官方cloud image版本／SHA512查询、fnm／Node／npm下载或缓存策略；不自动给已有VM换源。

软件包和安全更新均使用所选镜像的HTTPS地址，保留Debian archive keyring签名校验。Cloud-init在早期`write-files`阶段替换`/etc/apt/sources.list.d/debian.sources`并清空传统`sources.list`，`apt.preserve_sources_list=true`防止后续模块再生成默认源。只启用`trixie`、`trixie-updates`和`trixie-security`的`main`；不保留cloud image默认的`mirror+file`、`deb-src`或backports。GPU安装按同一镜像补充`non-free-firmware`，不禁用签名或证书验证。镜像同步或网络故障仍可能导致下载失败；检查日志后再继续安装，不自动改回其他源。

基础系统使用经过校验的Debian13 generic amd64 cloud image。先完成基础系统和软件桌面，再安装匹配客机内核的GPU模块、接入已准备的设备。镜像、fnm、Node、MCP、Codex和驱动的实际版本保存在部署记录；不会把仓库外的实验日期路径、PID、固定BDF或旧账号资料打包进去。

新建VM由Cloud-init在首次启动时创建4 GiB的`/var/lib/onepve-agent/swapfile`，权限0600，并写入`/etc/fstab`供开机自动启用。这会使用VM系统盘4 GiB，虚拟系统盘仍为最低32 GiB；薄置备存储的宿主空闲预留相应提高到24 GiB。客机安装器在安装桌面和编译驱动前检查文件大小、权限、启用和持久化状态，失败就停止并提示查看Cloud-init日志，不假定初始化成功。不修改swappiness，不增加迁移或修复已有VM的功能。安装记录包含处理结果，运行验收和菜单摘要显示实际swap容量与路径；VM内可用`swapon --show`和`free -h`查看。

镜像缓存位于宿主`/var/cache/onepve/images`，与VM磁盘选择的PVE存储无关。同版本镜像通过SHA512校验后直接复用；只有旧版本时，创建阶段会列出构建版本、文件大小和路径，输入序号复用，回车下载最新版。线上版本查询失败仍检查本地；下载失败也会再次提供可用本地镜像。无法取得线上镜像且无校验通过的本地镜像时才中止；离线列表回车表示主动取消。预检只列候选，不询问或写缓存；实际创建时再选择。直接使用CLI时，本地镜像选择同样从stdin读取，提示写stderr，stdout保持JSON。

每张镜像下载校验完成后立即保存同名`.qcow2.json`摘要记录，兼容旧`prepared.json`，后续准备失败也不影响离线复用。只有文件而没有可信摘要时，会尝试获取该固定版本的官方SHA512；无法取得或校验失败的文件会被跳过，不凭文件名信任，也不覆盖损坏缓存。镜像可离线复用不代表全部安装可离线完成：尚未缓存的运行时和Debian软件包仍需网络。下载时显示服务器声明的预计大小（未提供则显示未知），完成和复用时显示实际文件大小。

客机核显编译产物单独缓存在宿主`/var/cache/onepve/driver-binaries`。首次安装正常编译；之后按精确客机内核版本、架构、驱动版本和固定源码SHA256查找。客机还会比较实际内核`Module.symvers`和配置摘要，校验四个模块的SHA256、版本、vermagic及全部内核／伴随模块符号CRC，通过后经DKMS导入并安装，跳过编译。缺失、不匹配或校验失败会回到正常DKMS编译，使用DKMS默认并行度；源码、headers和固件依然按原流程准备。

缓存仅包含四个模块与清单，不保留源码、完整编译目录或其他VM的签名私钥；压缩包限制512 MiB，展开限制1 GiB，拒绝链接、稀疏文件、额外成员和越界路径。内核启用模块签名强制／Secure Boot策略时，不复用其他VM的模块，回到本机DKMS构建与签名流程，不关闭保护。缓存命中、编译原因、路径、大小及保存失败原因记录在状态`driver_cache`中；缓存导出或宿主保存失败只作提示，不撤销当前已安装的驱动。安装任务恢复时保留正在运行任务的脚本和输入；已完成任务遇客机内核变化才准备新任务。删除宿主缓存不会卸载现有VM驱动，但下次创建可能重新编译。

## 连接

VM内默认端口如下：

| 端口 | 用途 |
|---|---|
| 22 | SSH；通过当前网络或已有VPN／转发连接 |
| 9222 | Chromium CDP，仅VM回环 |
| 8931 | Playwright MCP，仅VM回环 |
| 5900 | 共享当前桌面的VNC，仅VM回环 |
| 6080 | noVNC网页与WebSocket，仅VM回环 |

本机默认通过SSH转发 `16080→6080` 和 `18931→8931`。noVNC免额外密码依赖这条SSH认证边界；代理另有精确Host／Origin白名单和防iframe响应头。不能把6080或5900暴露到公网／局域网后继续沿用此免密配置。

前端项目放在 `agent` 用户工作目录，开发服务默认绑定VM回环地址。需要本机查看时，另加明确的SSH本地转发，不修改PVE网络。Node任务用fnm绝对路径和记录的完整版本启动；系统服务不依赖`.bashrc`。

Codex CLI已预装，账户由用户在新VM上重新授权。新建系统不复制旧的Codex token、浏览器账号或客户端私钥。真实网站登录由用户首次完成，自动验收不会索取账号密码。

Windows客户端的SSH别名、可信主机公钥更新、隐藏重连脚本及停止方法见 [Windows查看与接管](windows-client.md)。脚本只维护SSH转发，不安装本机MCP。首次授权由普通用户在远端执行 `/opt/onepve-agent/bin/agent-codex login --device-auth`。

## 接管与重启

1. 停止Codex当前浏览器任务，把noVNC从只读改为允许输入。
2. 点击“接管浏览器”并确认。只有MCP停止；Chromium、标签页和SSH中的构建任务继续运行。
3. 操作后点击“交还Codex”并确认，将noVNC切回只读。
4. Codex继续时先重新列出标签页和读取页面，不重放中断前的输入。

手动标记持久保存，VM重启后MCP仍暂停；须显式交还。浏览器在首次启动前已设置“继续上次会话”，普通用户D-Bus与默认keyring保持同一套；GPU桌面另有私有Wayland runtime，不替换XFCE救援桌面总线。控制面板主窗定位规则不套用到确认对话框。

PVE图形控制台在GPU模式下主要显示XFCE救援桌面，日常浏览器由独立noVNC查看。关闭查看网页、MCP或SSH隧道不等于关闭VM浏览器。

## 状态、验收与继续安装

菜单03／08先显示关键摘要，再询问是否用nano查看原始JSON；回车或N跳过，Y只读打开。原始结果仅临时保存在默认`/tmp`下的私有目录，权限0600，查看结束后清理。查看器退出或缺少nano不会改变安装结果；安装进度、镜像选择和错误提示仍实时显示。直接调用CLI的默认JSON输出保持不变。

菜单08提供状态、验收与继续未完成安装。创建前的存储列表会列出目录或卷组／存储池、实际挂载来源和可识别的物理盘；目录位于宿主根文件系统时会明确提示共享空间。例如，`ai-dev`这样的存储名称和`/var/lib/ai-dev-storage`这样的目录不代表独立磁盘；以当前列表中的实际配置和底层设备为准。附加探测失败时显示未识别，不修改挂载或激活卷，存储默认值仍按可用容量排序。

终端安装会显示镜像下载／校验、磁盘导入、Cloud-init、桌面和运行时安装、客机驱动、GPU验收等实际阶段，并每30秒显示等待提示。耗时按本次命令计算，重新运行“继续安装”会重新计时，不代表重新启动客机任务。宿主状态位于`/var/lib/onepve/agent/<VMID>/state.json`；安装和驱动日志位于VM内输出的`/var/lib/onepve-agent/jobs/*.log`，需要客机root权限读取。进度只写终端stderr，stdout继续提供JSON结果，重试和回滚语义保持不变。

进度行同时显示“当前环节预计剩余”。镜像、Node等宿主文件下载按实际字节量、服务器提供的总大小和当前下载平均速度估算，每约5秒更新已下载量、速度与百分比；没有总大小或速度样本时显示未知。下载完成会进入独立校验阶段，校验通过才报告完成。

新客机安装器把APT原生状态写入已有任务日志；宿主仅在交互终端中每约10秒读取最多16 KiB日志尾部，显示软件包下载的原生剩余时间，以及解包／配置的百分比。配置、DKMS编译、缓存导入和验收没有可靠总工作量时显示未知；这里的预计只针对当前环节，不是整个安装任务的倒计时。没有新进度、采样失败、阶段切换或估计过期时清除旧倒计时，不能把“等待中”当作实际进展。日志采样失败不改变安装结果，也不会启动第二份任务。

旧版已上传或正在执行的客机任务没有APT状态行时仍显示未知，不热替换其脚本。更新仓库后，新建工作机会使用新安装器；继续观察旧任务可显示已有日志信息，但不会凭旧日志或包序号推算剩余时间。重连后的首次日志样本不提供ETA，观察到新的状态后才恢复估算。

只读计划和`--dry-run`不创建缓存、VM、配置或状态。部署记录位于宿主 `/var/lib/onepve/`，不要手工清空记录来绕过所有权或版本检查。

验收分开记录基础系统、SSH、fnm运行时、MCP输入／点击／截图、noVNC画面与键鼠、接管、重启恢复。GPU必须通过原生EGL、精确VF文件句柄以及Intel WebGL1/2绘制检查；仅进程存在或服务active不足以通过。Cookie检查使用合成会话值，不把真实Cookie或keyring内容写入日志。

失败或SSH断线后先看状态和日志。继续安装只接续本次拥有的VM和确定的阶段；状态不明确、设备被占用或配置被外部修改时会停止，不能假定重试安全。

## 重建与恢复边界

普通创建拒绝已有VMID。显式重建会删除指定VM及其磁盘，不自动备份，必须输入相同VMID确认。希望保留数据时应先使用PVE的完整VM备份；配置备份不能代替磁盘备份。

手动删除VM后，若同一VMID仍有旧部署记录，预检会提示该记录。创建时取得操作锁，再通过PVE集群VMID检查、本地／集群配置和QEMU PID文件检查确认VM已删除，询问“删除旧部署记录并继续创建？”；回车、N或输入结束均取消，旧记录保留。输入Y后先准备安装文件，再复查VMID空闲和记录未变，最后原子替换该VMID的`state.json`并继续创建。锁文件、旧打包文件以及镜像／驱动缓存保留；此入口仅处理已删除VM的旧记录。VMID仍被占用、检查失败或记录异常时停止。

重建前记录需要保留的MAC、公钥和转发目标，确保旧VM已释放设备。固定FRPC目标还需明确配置静态地址或已有DHCP保留，不能以原MAC推断新VM地址。新VM的SSH主机密钥必然变化：先经PVE／QEMU Guest Agent可信读取新的公钥与指纹，再更新客户端对应的专用known_hosts条目；不要关闭`StrictHostKeyChecking`或复制旧主机私钥。

GPU初始化或验收失败时，撤销新VM本次GPU接入，回退软件桌面并保留诊断、profile、MCP和noVNC。此时结果明确为“GPU失败／软件桌面可用”，不能作为加速通过。宿主共享PF、已有外部VF服务和其他VM不属于此回退范围。

无备份删除的旧VM不能靠回滚新配置恢复。新工具的恢复只操作部署记录证明归属且未被外部修改的文件、设备和新资源，不调用旧菜单07的全量覆盖恢复。
