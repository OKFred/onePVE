# Agent 工作机

## 创建前

先在菜单03完成宿主显卡准备，再到08创建系统。无GPU也可以直接建立软件桌面；08不会为了安装工作机而更换宿主内核、安装宿主显卡驱动、清零已有VF或修改网桥。

向导读取当前节点的活动网桥和支持 `images` 的可用存储，并取得空闲VMID。配置不得低于4 vCPU、固定8192 MiB和32 GiB系统盘，默认使用此配置。SSH只接受公钥，不接受或复制客户端私钥。IP、MAC、查看端口可在向导中明确指定，供重建后连接核验。

开头列出的存储和网桥是候选项，随后按VMID、名称、存储ID、网桥的顺序询问。存储和网桥各选一个；VM仅创建一张网卡并连接所选网桥。新目录需先在PVE注册为支持磁盘映像的存储，再在向导中填写它的存储ID。

网络默认使用DHCP。保留MAC或填写“期望IPv4地址”不会把该地址分配给VM，DHCP仍可能给出新地址。SSH／FRPC依赖固定目标时，选择`static`并填写未被占用的IPv4/CIDR、同子网网关和单个IPv4 DNS；静态模式的期望地址须与该IPv4一致。也可以使用路由器上已经配置好的DHCP保留，工具不会修改PVE网桥或路由器配置。

命令行对应参数为 `--address 192.168.50.30/24 --gateway 192.168.50.1 --nameserver 192.168.50.1`，地址应替换为实际网段；只传`--expected-ip`仅做连接结果核验。先查看计划，再创建或显式重建。网络配置写入新VM的Cloud-init，不修改宿主网络。

基础系统使用经过校验的Debian13 generic amd64 cloud image。先完成基础系统和软件桌面，再安装匹配客机内核的GPU模块、接入已准备的设备。镜像、fnm、Node、MCP、Codex和驱动的实际版本保存在部署记录；不会把仓库外的实验日期路径、PID、固定BDF或旧账号资料打包进去。

## 连接

VM内默认端口如下：

| 端口 | 用途 |
|---|---|
| 22 | SSH；通过当前网络或已有VPN／转发连接 |
| 9222 | Chromium CDP，仅VM回环 |
| 8931 | Playwright MCP，仅VM回环 |
| 5900 | 共享当前桌面的VNC，仅VM回环 |
| 6080 | noVNC网页与WebSocket，仅VM回环 |

本机默认通过SSH转发 `16080→6080` 和 `18931→8931`。noVNC免额外密码依赖这条SSH认证边界；代理另有精确Host／Origin白名单和防iframe响应头。不能把6080或5900暴露到公网／局域网后继续沿用此免密配置。

前端项目放在 `agent` 用户工作目录，开发服务默认绑定VM回环地址。需要本机查看时，另加明确的SSH本地转发，不修改PVE网络。Node任务用fnm绝对路径和记录的完整版本启动；系统服务不依赖`.bashrc`。

Codex CLI已预装，账户由用户在新VM上重新授权。新建系统不复制旧的Codex token、浏览器账号或客户端私钥。真实网站登录由用户首次完成，自动验收不会索取账号密码。

Windows客户端的SSH别名、可信主机公钥更新、隐藏重连脚本及停止方法见 [Windows查看与接管](windows-client.md)。脚本只维护SSH转发，不安装本机MCP。首次授权由普通用户在远端执行 `/opt/onepve-agent/bin/agent-codex login --device-auth`。

## 接管与重启

1. 停止Codex当前浏览器任务，把noVNC从只读改为允许输入。
2. 点击“接管浏览器”并确认。只有MCP停止；Chromium、标签页和SSH中的构建任务继续运行。
3. 操作后点击“交还Codex”并确认，将noVNC切回只读。
4. Codex继续时先重新列出标签页和读取页面，不重放中断前的输入。

手动标记持久保存，VM重启后MCP仍暂停；须显式交还。浏览器在首次启动前已设置“继续上次会话”，普通用户D-Bus与默认keyring保持同一套；GPU桌面另有私有Wayland runtime，不替换XFCE救援桌面总线。控制面板主窗定位规则不套用到确认对话框。

PVE图形控制台在GPU模式下主要显示XFCE救援桌面，日常浏览器由独立noVNC查看。关闭查看网页、MCP或SSH隧道不等于关闭VM浏览器。

## 状态、验收与继续安装

菜单08提供状态、验收与继续未完成安装。创建前的存储列表会列出目录或卷组／存储池、实际挂载来源和可识别的物理盘；目录位于宿主根文件系统时会明确提示共享空间。`agent-browser`只是存储名称，`/var/lib/agent-browser-storage`只是目录，不代表独立磁盘；以实际挂载和底层设备为准。附加探测失败时显示未识别，不修改挂载或激活卷，存储默认值仍按可用容量排序。

终端安装会显示镜像下载／校验、磁盘导入、Cloud-init、桌面和运行时安装、客机驱动、GPU验收等实际阶段，并每30秒显示等待提示。耗时按本次命令计算，重新运行“继续安装”会重新计时，不代表重新启动客机任务。宿主状态位于`/var/lib/onepve/agent/<VMID>/state.json`；安装和驱动日志位于VM内输出的`/var/lib/onepve-agent/jobs/*.log`，需要客机root权限读取。进度只写终端stderr，stdout继续提供JSON结果，重试和回滚语义保持不变。

只读计划和`--dry-run`不创建缓存、VM、配置或状态。部署记录位于宿主 `/var/lib/onepve/`，不要手工清空记录来绕过所有权或版本检查。

验收分开记录基础系统、SSH、fnm运行时、MCP输入／点击／截图、noVNC画面与键鼠、接管、重启恢复。GPU必须通过原生EGL、精确VF文件句柄以及Intel WebGL1/2绘制检查；仅进程存在或服务active不足以通过。Cookie检查使用合成会话值，不把真实Cookie或keyring内容写入日志。

失败或SSH断线后先看状态和日志。继续安装只接续本次拥有的VM和确定的阶段；状态不明确、设备被占用或配置被外部修改时会停止，不能假定重试安全。

## 重建与恢复边界

普通创建拒绝已有VMID。显式重建会删除指定VM及其磁盘，不自动备份，必须输入相同VMID确认。希望保留数据时应先使用PVE的完整VM备份；配置备份不能代替磁盘备份。

重建前记录需要保留的MAC、公钥和转发目标，确保旧VM已释放设备。固定FRPC目标还需明确配置静态地址或已有DHCP保留，不能以原MAC推断新VM地址。新VM的SSH主机密钥必然变化：先经PVE／QEMU Guest Agent可信读取新的公钥与指纹，再更新客户端对应的专用known_hosts条目；不要关闭`StrictHostKeyChecking`或复制旧主机私钥。

GPU初始化或验收失败时，撤销新VM本次GPU接入，回退软件桌面并保留诊断、profile、MCP和noVNC。此时结果明确为“GPU失败／软件桌面可用”，不能作为加速通过。宿主共享PF、已有外部VF服务和其他VM不属于此回退范围。

无备份删除的旧VM不能靠回滚新配置恢复。新工具的恢复只操作部署记录证明归属且未被外部修改的文件、设备和新资源，不调用旧菜单07的全量覆盖恢复。
